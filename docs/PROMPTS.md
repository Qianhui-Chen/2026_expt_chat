# 实验提示词结构

实现位置：`backend/app/conditions.py`。两个自变量独立组合，共四组：

- A / ingroup：理解用户感受，认可情绪与立场，持续支持用户。
- B / outgroup：明确反对用户当前判断，指出证据不足或片面，考虑对方可能的道理并引导换位理解。
- 奇数 / early_advice：第 1–8 轮直接提供意见。
- 偶数 / late_advice：第 1–4 轮分析并引导提问；第 5–8 轮提供意见。

回复仍按实验结构组织内容，不设置各段硬性字数上限。提示模型将每轮完整回复尽量控制在 400 字以内。

四种组合均以每轮 400 字以内为生成目标。后端不会因为篇幅或格式检查失败而拦截回复；检查可用于请求模型重写，但最终始终显示和保存模型最后生成的内容。

late_advice 的前四轮依次围绕以下主题提问：冲突细节；用户的感受与解释；过往互动与关系；双方性格及沟通习惯。每轮只使用一个主题，并在该主题下提出两个不同的子问题。主题只指定提问方向，不要求逐字输出；应结合对话自然调整措辞。已知信息不重复提问，也不编造性格或动机。

late_advice 前四轮固定依次输出：2–3句立场、4–6句独立分析、一句自然且谦逊的澄清过渡语，以及当轮主题下的两个问题。分析不重复立场或提供建议，应从与当前对话相关的新颖角度提供客观、有说服力且有见地的理解。后四轮依次输出2–3句立场、一句结合语境自然引出可操作方法或意见的过渡句、三条建议和一个推进对话的问题，不生成独立分析段。early_advice 每轮采用立场、建议过渡句和三条建议的结构，不在末尾提问。


由于回复需要先完成检查与可能的重写，聊天页会在通过检查后一次显示整条回复，不再逐字显示尚未核验的草稿。

Outgroup 先在系统提示之后、真实历史之前注入一组隐藏的 user-assistant challenge 指令，再由 DeepSeek 生成初稿。初稿会先检查当轮所需的问题数量，以及意见阶段是否包含恰好三条项目符号建议；不合格时最多重写一次。之后进行一次低温度 DeepSeek 过滤，删除确认、肯定、共情、站队和复述内容。过滤器不新增建议或立场。过滤调用失败时保留已经完成结构检查的回复，避免阻断对话。Ingroup 不注入 challenge 指令，也不经过该过滤器。

意见阶段使用八个指定主题。early_advice 第 1–8 轮依次各用一个主题，每轮拆成三条子建议。late_advice 第 5–8 轮依次使用主题 1+2、3+4、5+6、7+8，每轮共给三条建议，整体覆盖当轮两个主题。每条都单独写成「- **小标题**：建议内容」。两种建议时机均使用完整对话历史，不再生成或注入用户画像。
